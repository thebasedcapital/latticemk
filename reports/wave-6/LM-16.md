# LM-16: correctness-gate mutation analysis

Inspired by "Measuring the Checker: Mutation Analysis for GPU-Kernel Benchmark Oracles" (arXiv 2609.22220).
Started by a GPT-6.1 Sol agent, continued by a Sonnet 5.5 agent (campaign, jitter v2, extra tests), finished by the
integrator (final reruns, `mutation/summarize.py`, this report).

## Gate decision

```
                     gate v2.1 alone      + extra tests        kill rate change
Qwen3-0.6B (201)     72.1%                89.1%                +17.0 points
Qwen3-1.7B (114)     71.9%                83.3%                +11.4 points
synchronization      63.0% / 76.0%        100% / 100%          every sync mutant now caught
precision            43.3% / 33.3%        46.7% / 33.3%        the gate's blind spot
```

**Gate v2.1 is not sufficient on its own.** It missed 28% of non-equivalent single faults, including every
conditional fault (long-context attention, sampler tail, CTA-local races). The extra tests below fix all
synchronization and most bounds/attention misses and are adopted as the new gate tier. A remaining class of real
single-layer bugs is invisible to any logit-tolerance gate at this engine's precision (see honest negatives).

## Status

- `mutation/mutate.py`: builds single-fault copies of the known-correct kernels (`kernels/megakernel_v2/mega2.cu`,
  the 1.7B scale kernel) under `mutation/build/` (git-ignored). Originals are never edited. One operator, one site
  (layer, projection) per mutant; the clone is dispatched only at that site.
- `mutation/gate.py`: runs a copy of the v2.1 gate against each mutant library with a cached HF fp32 fake-quant
  reference. Tolerances unchanged (absolute 0.5, 1.25x the original kernel's value, near-tie rule, bitwise repeat).
- `mutation/extra_tests.py`: tests run on gate survivors: sampler token check, contexts 129/257/1100 (cross the
  attention-slice and position-128 boundaries), adversarial prompts (number reversal, code completion), lm_head row
  permutations that move the top-1 token onto tail rows, multi-step vs single-step launch equality, extra repeats,
  timing jitter (random `__nanosleep` around barriers plus 2-4 us slow warps), and a logit-distribution check.
- `mutation/summarize.py`: kill matrix from `mutation/results.jsonl`.
- Campaign: 212 Qwen3-0.6B mutants (201 non-equivalent, 11 equivalent, 0 compile failures, includes 8 schedule-only
  validator mutants) and 120 Qwen3-1.7B mutants (114 non-equivalent, 6 equivalent) `[measured, mutation/results.jsonl]`.
- Controls: 4 no-op mutants (GEMV, grid barrier, attention, sync clones) give logits identical to the original
  (difference 0.0), so the harness itself adds no noise `[measured]`.

## Honest negatives

- **Synchronization faults pass the v2.1 gate easily.** Dropped `__syncthreads`, early flag release and removed
  lm_head grid barriers produced logits identical to the original on the base cases: the race window never opened.
  Only timing jitter and extra repeats exposed them. Bitwise determinism over two runs is not race detection.
- **Conditional faults are invisible at 64 tokens of short prompts.** Long-context attention faults and sampler tail
  faults had exactly the original kernel's difference (0.2114 on 0.6B), i.e. the faulty code never ran.
- **The logit gate cannot see real single-layer bugs below the engine's own noise.** 41 non-equivalent mutants
  survive everything (22 on 0.6B, 19 on 1.7B): single-site fp16 accumulation, truncated reductions, round-toward-zero,
  halved attention scale at one layer, and RoPE position off by one at one layer. Each moves logits by 0.008-0.31
  against the original kernel, but stays inside the tolerance against HF because the engine's own deviation is
  0.21 (0.6B, fp16 partials) and 0.05 (1.7B, fp32). Some mutants land closer to HF than the original does. A
  logit-tolerance gate set by this noise cannot separate these bugs from legitimate reordering.
- One 1.7B long-context attention fault (`long_skip_last-L7`) is never exercised even by the 1100-token context case
  (difference 0.0 against the original): the extra contexts do not reach that attention slice on 1.7B.
- The schedule validator only sees grid-wait edges. CTA-local barriers and early release are not events in Schedule
  IR v1 (`NOT_APPLICABLE`), confirming the wave-4 finding that a validated schedule does not prove the kernel.
- Equivalence is observed (identical logits on all base and extra cases), not proved.

## Open threads

1. **Adopt the extra tests as gate tier 2** for every kernel change (about 16-31 s per candidate).
2. **Per-layer check (proposed fix for the blind spot):** teacher-force the reference and compare each layer's
   hidden state against HF with a per-layer tolerance calibrated on the original kernel. A one-layer bug (halved
   attention scale, RoPE off by one) should stand out at its own layer even when final logits stay inside the noise.
   Not implemented in this package.
3. **Regression mode:** when a change is declared numerics-preserving, require bitwise-equal logits against the last
   accepted kernel. Controls show 0.0 drift, so this kills every surviving mutant here at zero tolerance cost.
4. Extend extra contexts for 1.7B so every attention slice is exercised (cover `long_skip_last-L7`).
5. Validator: extend Schedule IR beyond grid waits, or add host-guided race analysis (see HGRD, arXiv 2604.02106).
