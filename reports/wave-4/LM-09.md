# LM-09: compressed KV inside the megakernel

2026-09-30. Quadro RTX 4000 (sm_75), driver 610.57.04, unlocked clocks. Engine: `kernels/megakernel_kv/`; harness: `bench/lm09/`; codec: `kvcodec/codec_lm09.py`. No git repository, so result rows use `commit=nogit`.

## 1. Gate decision

| Gate | Decision | Evidence |
|---|---|---|
| KV quality, ppl <= 13.29 | **PASS** | [measured, `bench/lm09/eval_codec.py`, `codec_results.jsonl`] K8 per-token + V4 per-token, both group 128, reaches **12.806** on all 146 WikiText-2 windows. The same evaluation protocol's fp16 KV baseline is 12.66 [measured, `kvcodec/eval.py`, `reports/wave-2/LM-07.md`]. |
| Codec implementation and schedule | **PASS** | [measured, `bench/lm09/quant_parity.py`] K and V quantizer output matches the Python codec on captured KV: zero code mismatches out of 16,384 coordinates per kind, zero metadata mismatches out of 256 half values per kind. [measured, `validator/target/release/schedcheck`] ACCEPT for ctx 128, 2048, 8192. |
| 64-token correctness | **FAIL** | [measured, `bench/lm09/check_correctness.py`] With 64 teacher-forced tokens on each of 3 prompts, max absolute logit error is **3.2162** versus **0.3920** for v2 with its fp16-KV HF reference on the same forced token sequences; gate limit is min(0.5, 1.25 x 0.3920) = **0.4900** [derived]. Two independent KV engine passes were bitwise identical [measured]. |
| 8192-context speed kill, >= 1.3x v2 | **KILL** | [measured, `bench/lm09/bench.py`, `results.jsonl`] Interleaved diagnostic: 6.288 ms KV vs 4.549 ms v2, **0.724x** v2 throughput. Timing is expressly invalid for a speed claim because correctness failed. No further tuning or 16384 run after this kill. |

**Outcome: killed. Do not ship the compressed engine.** The quality pass alone does not rescue failed logits and lower throughput.

## 2. Status per work-package item

- [measured, `bench/lm09/eval_codec.py`] Searched K per-channel INT4 over 64/128-token groups with residuals and K per-token INT8, paired with V per-token INT4/INT8, including clip-shrink and min/max RTN. The fewest bytes among tested quality passes were **1600 B/token/layer**, or **6.25 bits/coordinate** including fp16 scale and offset (K 8.25, V 4.25 bits/coordinate) [derived, `kvcodec/codec_lm09.py`]. The kernel appends packed K8/V4 with fused attention dequantization; current-token K/V stay exact fp16 [implementation, `kernels/megakernel_kv/megakv.cu`].
- [measured, nvcc `-Xptxas -v`] Timed `megakv_kernel`: 64 registers, zero spills, 20,352 B shared memory/CTA. [measured, `bench/lm09/quant_parity.py`] The actual CUDA append quantizer and Python fake-quant produce bitwise identical codes and half metadata for the same captured fp16 inputs. This does not establish end-to-end numerical parity: different layer activations produce different inputs to that quantizer.
- [measured, `validator/target/release/schedcheck`] IR v1 `kernels/megakernel_kv/schedules/mkv_ctx{128,2048,8192}.json` all ACCEPT.
- [measured, `bench/lm09/check_correctness.py`] Free-running greedy matches are **2/64, 44/64, 23/64** for the 3 prompts. Teacher forcing holds the input sequence fixed and exposes the numerical gap: per-prompt maximum absolute logit differences **3.2162, 2.3834, 1.4227**. Every argmax mismatch on the forced sequence qualifies as a near-tie under the gate's margin rule; the six `(prompt, step, margin, max_diff)` cases are `(0,1,0.09396,0.80106)`, `(0,56,0.00025,3.21622)`, `(1,35,1.00384,1.40495)`, `(1,63,0.26019,1.51890)`, `(2,20,0.09373,0.56561)`, `(2,27,0.03626,0.53763)` [measured]. Logit magnitude, not argmax, fails the gate.
- [measured, `bench/lm09/bench.py`] `bench/lm09/results.jsonl` has 6 diagnostic rows, alternating engine order within each of 25 timed rounds per context. Median, p10, p90, SM clock, actual packed bytes, driver and correctness status are recorded per row. No 16384 row: 8192 already triggered the kill line. Memory feasibility at 16384 was not determined [unmeasured].

At 8192, both engines stream **316.617 MB/token** of packed weights [measured, `bench/lm09/bench.py`]. Packed KV saves **572.522 MB/token** [derived]. Against the measured 406.7 GB/s ceiling, the ideal byte floors are v2 **3.089 ms** (0.779 weights + 2.310 KV) and compressed **1.681 ms** (0.779 weights + 0.902 KV) [derived, `bench/lm09/results.jsonl`, `hw/hw.json`]. Observed excess over those lower bounds is 1.461 vs 4.607 ms, respectively [derived]. This **3.146 ms** excess-gap increase exceeds the 1.408 ms byte-floor saving; it is not a measured pure decode cost and also includes phase serialization and compute. Net measured latency rises **1.738 ms/token** [measured/derived, `bench/lm09/bench.py`].

## 4. Honest negatives

- The quality-first format passes perplexity but fails numerical correctness by **6.56x** relative to the 0.4900 limit [derived, `bench/lm09/check_correctness.py`]. Its quantizer alone is bit-exact on captured input; the run-to-run engine replay is also bitwise deterministic [measured, `bench/lm09/quant_parity.py`, `check_correctness.py`]. The reference uses fp32 linears with fp16 inputs to its KV quantizer, while the persistent kernel's matvec and activation stream are fp16. Packed-cache reconstruction versus Python fake-quant on their *different model-generated inputs* already differs by relative K **0.0369** and V **0.1426** on the shared first prompt prefix [measured, `check_correctness.py`]. This comparison does not prove a codec implementation defect; it shows why bit-exact quantizer input probes and model-level parity must be kept distinct.
- INT4 K per-channel variants tested here miss the 13.29 perplexity target, even with clipping and a 256-token fp16 residual [measured, `bench/lm09/codec_results.jsonl`]. The smallest passing point still costs 6.25 bits/coordinate [derived].
- The packed engine **slows down** at all three measured contexts despite a 2.56x reduction in KV-cache bytes [measured, `bench/lm09/bench.py`; derived, `kvcodec/codec_lm09.py`]. A byte-only roofline prediction is not a latency prediction on this kernel.
- The initial diagnostic JSONL generator incorrectly counted the compressed K+V byte total twice. `bench/lm09/bench.py` and `lm09.py` now count 1600 B/token/layer once; the 6 existing rows' byte-derived fields were corrected without re-timing. The elapsed-time distributions are untouched [derived, `bench/lm09/results.jsonl`].
