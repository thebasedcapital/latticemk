# LM-10 — synchronization fork: KILLED at ctx 128

Quadro RTX 4000, sm_75; driver 610.57.04; clocks unlocked. Kernel
`kernels/megakernel_sync/mega3.cu`, harness `bench/lm10/`, commit `nogit`.
INT4-g128 RTN weights and fp16 KV format are identical to megakernel-v2.

## 1. Gate decision

| Gate | Decision | Evidence |
|---|---|---|
| LM-10 speed, at least 1.05x v2 at ctx 128 | **KILL** | 0.9282x: v2 1.7309 ms/token, sync fork 1.8649 ms/token; 25 alternating eight-step launches per engine `[measured]` (`bench/lm10/bench.py` → `results.jsonl`). |
| Correctness v2.1, 3 prompts × 64 teacher-forced steps | **PASS** | Max abs logit error 0.391972 for fork and 0.391972 for v2 against the same HF fp32 fake-quant reference; 0 unexcused argmax errors, two fork passes bitwise identical `[measured]` (`bench/lm10/check_correctness.py`). |
| Schedule safety | **ACCEPT** | `schedcheck` accepted all 3 ctx-specific IR v1 files `[measured]` (`kernels/megakernel_sync/sched_gen3.py`, `validator/target/release/schedcheck`). |

The 128-token kill line is binding. No 2048/8192 **performance** timings or
post-kill tuning were attempted. `results.jsonl` deliberately has only two
ctx-128 rows; the 8192 **debug phase trace** below is diagnostic, not a
benchmark or a speed claim.

## 2. Status and merge map

The fork builds and executes. `libmega3.so` is the timed kernel;
`libmega3prof.so` stamps phase edges; `libmega2prof.so` stamps v2. The
SMEM/layout of `kc` and `vc`, their fp16 contents, INT4 codes and metadata,
and `part[32][130]` are unchanged `[measured]` (`mega3.cu`,
`bench/lm10/check_correctness.py`). Schedule IR has 5,112 tasks and 1,150
flags for each context `[measured]` (`sched_gen3.py`, `schedcheck`).

Changed regions in `mega3.cu` for a KV-format merge:

| Region | Change | KV merge constraint |
|---|---|---|
| `P2`, `arrive`, `wait_bar`, `wait_qkv`, `zero_counters` | Per-(step,phase) arrival counters and per-CTA `done[36]`; head waits on only q/k/v row producers. A single cumulative counter was unsafe because future-phase arrivals could satisfy a previous phase's wait. | No change to cache address arithmetic. Keep phase-indexed full waits when merging. |
| `prefetch_l2`, `mega3_kernel` phase transitions | Prefetch own next GEMV codes/meta after arrival, before full waits. CTAs 32–35 prefetch o weights during attention. | Cache read/compression work belongs inside `attn2`; these flags only gate qkv/part/GEMV buffers. |
| `gemv_run`, `gemv2`, `block_argmax`, `argc2` | Floor-balanced CTA row ranges and lm-head argmax partial fused with its GEMV; separate argp phase removed. | Weight pointers/formats unchanged. |
| `u.wsc`, `attn2` | Two-pass warp score and value accumulation; still reads fp16 `kc/vc`, writes the original `part` layout. | This is the *only* changed attention body; replace its loads when merging a KV codec. |
| `mk3_init`, `mk3_mega`, `mk3_time_mega`; `bench/lm10/lm03b.py` | Extra counter/profile pointers, reset exact phase slots per launch; common packed weights, fp16 buffers for both engines. | Preserve cache dtype/layout until codec fork supplies its own. |

Only qkv→attention supports a partial read dependency in this implementation.
`pro_attnc` reads every attention partial before o GEMV; `pro_norm` reads the
whole o result before gate/up; `pro_silu` reads the full gate/up vector before
down GEMV `[measured]` (`mega3.cu`, `sched_gen3.py`). Per-head attention→o
or gate/up→down flags would require restructuring these prologues, not merely
replacing their full waits. The IR models one decode step; the GPU's next-step
qkv waits on CTA 0's `argc` arrival for `tok`.

**Where waiting went** `[measured]` (`phase_profile.py` → `phases.json`).
At 128, v2's per-phase maximum CTA barrier-wait sums are 82.4 µs qkv,
288.4 attention, 93.9 o, 106.7 gate/up, 94.6 down. The fork's corresponding
post-arrival/next-phase maxima are 96.3, 122.2, **407.1**, 96.4, 53.5 µs.
At 8192, v2 attention waits total 4696.3 µs across 28 layers (mostly idle
CTAs); the fork moves 4915.8 µs of such wait into o. These *maxima include
idle time overlapping useful work*, not an additive barrier tax. The
baseline's late-arrival→barrier-release tail sums 225.3 µs at 128 and
232.6 µs at 8192 for 143 barriers (debug build at roughly 1005 MHz);
the v2 wave-3 standalone empty-barrier probe at boost measured 1.04
µs/barrier `[measured]` (`phase_profile.py`, `bench/lm03b/stage_gemv.py`).

The requested position-half check finds no meaningful imbalance in v2:
mean attention CTA work per half is 8.804/8.979 µs at 128 and
164.071/163.586 µs at 8192. The fork's two-pass version is
11.994/12.096 and 171.106/170.455 µs respectively `[measured]`
(`phase_profile.py`). The two-pass attempt raises attention phase time;
it does not cure a measurable half split on these positions.

**Quality details** `[measured]` (`bench/lm10/check_correctness.py`).
Reference-forced fork maxima by prompt: 0.391972, 0.155650, 0.089200;
matched v2: 0.391972, 0.138042, 0.089200. No actual argmax mismatch; all
12 near-tie flags have matching argmax. `(prompt, step, reference margin)`:
`(0,1,.0572), (0,29,.0374), (0,43,.0841), (0,50,.1195),
(0,55,.1119), (0,56,.1640), (0,59,.1626), (1,20,.1368),

The full per-step maximum differences and token ids are printed by the

multi-step tokens against the same single-step trace `[measured]`.

## 4. Honest negatives

- **Killed at ctx 128**: extra bookkeeping, prefetch, two-pass attention and
  the fused sampler jointly lose 7.2% throughput despite removing one of
  143 barrier phases and shortening attention's direct wait `[measured]`
  (`bench.py`, `phase_profile.py`). This ablation does not isolate each
  ingredient; attributing the whole loss to one of them would be guesswork.
- The first implementation used *one cumulative global arrival count*,
  which let arrivals from phase N+1 release a wait for phase N. It produced
  run-to-run unstable greedy counts and sometimes sampled tokens disagreeing
  with the just-written logits, even while `schedcheck` accepted the IR:
  the IR specified per-phase flags but the kernel did not implement them.
  Separate counters for every `(step,phase)` fixed this. The retained smoke
  check fails on a sampler/logit or multi-step mismatch `[measured]`
  (`bench/lm10/smoke.py`; `mega3.cu` phase flags).
- The timed fork uses **64 registers with 20-byte spill stores and 44-byte
  spill loads per thread**, 24-byte stack frame and 38,144 B SMEM; v2 has
  64 registers and zero spills `[measured]` (nvcc `-Xptxas -v` for
  `mega3_kernel`, baseline `reports/wave-3/LM-03b.md`). This is *not* a
  justified zero-spill optimization; the measured speed loss means the
  fork must not replace v2.
- The original 0.25 full-64-step logit threshold would reject unchanged v2
  itself (max 0.391972); correctness v2.1 uses 0.5 absolute and 1.25×
  matched-v2 bounds, with repeatability and near-tie checks `[measured]`
  (`check_correctness.py`).
- No Nsight Compute was available on this machine `[assumed]`
  (environment handoff); byte-derived GB/s is not a DRAM counter reading.

## 5. Open threads

No further LM-10 changes under this kill decision. A future package could
test *one* dependency change at a time, retaining exact per-phase flags and
the sampler regression, before reintroducing prefetch or two-pass attention.
The wave-3 v2 engine remains the production baseline.
