# LM-08 — Fused separate-kernel INT4 decode engine

Wave-3 work package. Goal: keep LM-03's separate-kernel + CUDA-graph design
(which beat the persistent megakernel) but erase the ~170 tiny non-matvec
kernels by fusing them into GEMV prologues/epilogues and the attention
kernel. Target ~≤120 graph nodes/step. Ship or kill honestly.

## Gate

No kill line. Fused graph beats the LM-03 separate-kernel graph on every
measured context, interleaved, median of 25:

```
              baseline        fused
ctx         sep-graph      fused-graph    ratio
 128   3.106 ms 322 tok/s  2.225 ms 449.5 tok/s   x1.396   (SM 1155 MHz)
2048   3.433 ms 291 tok/s  2.439 ms 410.0 tok/s   x1.407   (SM 1845 MHz)
8192   6.016 ms 166 tok/s  4.225 ms 236.7 tok/s   x1.424   (SM 1845 MHz)
```

[measured, `bench/lm08/bench.py`, `results.jsonl` — both engines in the same
process, alternating, so ratios are clock-safe; the ctx-128 absolute times sit
at a low 1155 MHz clock, ratios unaffected]

Per LM-03's measured 2.311/3.433/6.030 ms wave-2 baselines, fused gains
~1.04x/1.41x/1.43x. At ctx 8192 the fused engine reaches 73.1% of the
measured 406.7 GB/s roofline (297 GB/s effective).

Node count per step: **169** (28 x [qkv-GEMV, k_attn, k_attnc, o-GEMV,
gu-GEMV, down-GEMV] + lm_head) vs ~285 for LM-03. A 141-node variant
(in-kernel attention combine) exists and was measured slower — see negatives.

## Correctness gate

`bench/lm08/check_correctness.py` (both graph and step modes, 3 LM-03
prompts, 64 greedy tokens, HF fake-quant INT4 fp32 reference):
**PASS, max |logit diff| = 0.1125** (LM-03: 0.129). All timed kernels 0
register spills (ptxas -v, 18 instantiations: 36–122 regs).

Long-context sanity: 200 steps at pos 2000+ track the LM-03 engine except a
single argmax tie flip at pos 2015 (logit diff at the flip ≈ 0.099, a
near-tie); fused engine is deterministic run-to-run for fixed state.

## What got fused (169 nodes, no megakernel)

Per layer, LM-03's [norm, qkv, qkra, attn, attnc, o, anorm, gu, silu, down,
anorm] becomes:

- **RMSNorm → GEMV prologue** (`PRO_NORM`, `PRO_EMBNORM`): every GEMV block
  re-normalizes the 1024-dim `x` into its own SMEM stage (warp-reduce sumsq
  + scale). L0's qkv also loads `emb[tok]` (embed fused).
- **q_norm/k_norm + RoPE + KV-append → attention prologue** (`k_attn<PREP>`):
  each attention block re-preps the query heads it needs into SMEM; the block
  owning `pos` additionally norms/ropes/appends K and copies V.
- **SiLU·mul → down-proj prologue** (`PRO_SILU`): reads `gu[i]`/`gu[3072+i]`,
  produces `h = silu(g)*u` into SMEM; gu-GEMV writes raw gate|up.
- **Residual adds → GEMV epilogue** (`EPI_RES`): o and down write `x` in
  place, adding `x + y` (with fp16 rounding of both terms to match
  anorm_exec numerics).
- **Final norm → lm_head prologue; argmax → lm_head epilogue**
  (`EPI_AMAX`): block-local argmax over each row stripe, packed as
  `(order-preserving float-bits << 32) | ~idx`, grid-wide `atomicMax` +
  arrival counter; last block writes `tok`, `tok_hist[pos]`, and **advances
  `pos`** — no tick/argp/argc kernels at all.
- **Attention combine** is a separate `k_attnc` (grid-parallel over heads,
  8 blocks) because the fused in-kernel variant measured slower.

## Measured ablations [measured, `bench/lm08/abl.py` + sweeps]

- GEMV fusion tax: fused 113-GEMV sequence = plain + 0.164 ms (norm
  prologue ~+1.4 µs on qkv/gu, silu prologue ~+4.8 µs on down, lm_head
  prologue+argmax ~+18 µs — worth it vs the ~1 ms of separate kernels
  they replace).
- In-kernel last-block attention combine: **30–60 µs/layer slower** than a
  separate `k_attnc` (straggler serialization), so the step keeps a combine
  node (169 nodes not 141).
- `PREP=1` (per-block q-norm/RoPE recompute) beats a separate `k_qkra` node
  (+3 µs vs +6 µs per layer) and removes a node.
- `k_attn` nt=512 (1 head/warp) beats nt=256 at all contexts.
- Attention splits `nslice = 36` for ctx ≤ 512 else `72` (swept; 144 loses).
- `k_attnc` grid 8 > 4 marginally.

## Phase split [measured, `fx_time_breakdown`, event pairs, non-graph]

| ctx | GEMV ms | attn ms | (169-node graph total) |
|-----|---------|---------|------------------------|
| 128 | 1.12    | 0.55    | 2.22                   |
|2048 | 1.21    | 0.60    | 2.44                   |
|8192 | 2.11    | 1.04    | 4.22                   |

Caveats: per-launch event deltas in a dense sequence partially overlap
dispatch; attn bucket includes k_attnc. Standalone `k_attn` at ctx 8192
measures ~135 µs/layer (241 GB/s on 33.6 MB of KV) — the residual
graph-total vs kernel-sum gap (~0.6–1.1 ms) is inter-kernel serialization:
each node must fully drain before the next starts. That tail-drain floor is
what a megakernel would need to remove, and wave-2's attempt paid more in
occupancy loss than it recovered.

GEMV parity: plain-GEMV graph vs LM-03's own GEMV sequence, interleaved,
is 1.71 ms vs 1.74 ms — identical kernels, no regression. (The 1.306 ms
wave-1 number came from a different boost-clock timing harness.)

## Honest negatives / known quirks

- The +164 µs GEMV fusion tax is real overhead relative to pure GEMV.
- In-kernel combine loses; don't retry without a straggler fix.
- The per-kernel event breakdown under/over-attributes under dispatch
  overlap; treat buckets as ±0.1 ms at long ctx.
- `fx_time_gemvseq` (113 non-graph GEMV launches) sometimes leaves a sticky
  CUDA error that poisons a following graph launch — kept for reference but
  not called from bench.py; run it standalone.
- Two statically-linked cudart runtimes (libmega + libfused) crash at
  process teardown; bench.py calls `fx_shutdown`/`mx_shutdown` and exits via
  `os._exit(0)` after writing results. Also: `fx_time_breakdown` originally
  wrote 6 floats into a 3-float buffer and destroyed-and-reused CUDA events —
  both fixed (static event pool, 3-float contract).
- ctx-128 rows were captured at 1155 MHz (thermal/power drift); ratios are
  valid, absolute tok/s is pessimistic (~1.87 ms at 1845 MHz in other runs).
