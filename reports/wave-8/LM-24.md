# LM-24 compaction-aware KV

```
v2       pos ------> RoPE + append + attention length
kvc      rope_pos -> RoPE, monotonic
         kv_len ---> append + attention length
compact  gather retained K/V -> scratch -> same cache prefix
         retained rotations and rope_pos unchanged
         old                 new                 delta
8k scan  8192 live rows      2048 live rows       -6144
RoPE     logical 8192        logical 8192        unchanged
```

## Gate decision

PASS. Both binding speed kill lines pass, scoped correctness passes, the real scripted session completes, and schedcheck ACCEPTs every emitted IR v1 schedule.

## Status

The owned fork is `kernels/megakernel_kvc/kvc.cu`; Python bridge is `bench/lm24/kvc.py`. The original v2 files are unchanged. Decode retains v2's phase order. The compaction event uses two GPU copy launches, gather then scatter, to avoid overlapping in-place-copy races. Scratch stores retained rows only and is allocated once by the bridge. `compact(keep_ranges)` accepts sorted disjoint half-open physical ranges whose endpoints cover complete Qwen3 chat turns. Both boundary tokens and trailing chat-template newlines stay inside each turn. The logical RoPE table can extend beyond the fixed physical cache capacity.

Scratch and CUDA timing events are preallocated. No device allocation occurs in `compact`; the Python bridge builds and uploads the physical row mapping per event. Tokenizer-boundary smoke checks include trailing newlines, keeping only the first turn, keeping the first plus the last turn, and an empty cache. `[measured, scoped CPU parser smoke; derived event allocation lifetime in kvc.cu]`

Method source: [KV-streams section 2](https://arxiv.org/html/2609.35750#S2). Retained cache entries are not re-prefilled or re-rotated. Earlier queries retain their original visibility in the one-pass reference; later queries cannot attend evicted rows.

The deterministic correctness transcript contains complete system, user, and assistant turns. Events keep the first turn plus the last two turns. The decode microbenchmark keeps the first plus the last seven 256-token turns, giving exactly 2048 retained physical rows. The real session uses the same retention policy. These are untuned examples. `[assumed policy, bench/lm24/reference.py, bench.py, session.py]`

`reference.py` runs HF fp32 fake-GPTQ once over the complete history with a custom 4D mask and logical `position_ids`. Each mask row describes the cache when that query was generated, including itself. It separately runs one uncompacted control forward over the same tokens. The reference's 113 matrices were checked for exact equality with decoded packed INT4 codes and fp16 metadata using `bench/lm11/ppl_llama_protocol.py::deq_int4`. `[measured CPU weight-equality and historical-mask smoke]`

The added `kv_len` buffer changes the initialization ABI, so the no-event regression uses an explicit raw-int32 logit-bit comparison rather than passing this library to the stock v2 gate. No claim of running stock gate tiers 1-3 is made.

Reproduce from the repository root:

.venv/bin/python bench/lm24/reference.py
scripts/gpu.sh timeout 285 .venv/bin/python bench/lm24/check_correctness.py

Reference generation is CPU-only. The reference tensor cache is generated data, not a new model checkpoint. All GPU jobs hold the shared lock and have an inner timeout.

- No-event speed relative to v2: 0.99296x at 128 and 0.99542x at 2048, above 0.97x. Compacted logical 8192 / physical 2048 reaches 0.99853x v2 at 2048, above 0.95x. Each timing case has 25 interleaved samples. `[measured, bench/lm24/bench.py -> timing.json]`

Max absolute difference is 0.190395 vs the fixed bound 0.215846. V2's uncompacted control error is 0.172677; bound is `min(0.5, 1.25*control)`. Real scripted session: 16,384 teacher-forced tokens, 64 deterministic complete turns, eight compactions, alternating engine order across nine segments. V2 takes 79.304 s; kvc takes 44.840 s including all eight events. This is a 1.7686x wall-time speedup and a 34.464 s reduction. Final kvc state is logical 16,384 / physical 4608; baseline physical state is 16,384. Both final logit vectors are finite. `[measured totals, derived ratio/delta, bench/lm24/session.py -> session.json]`

The session baseline is a copied v2 source with only `MAXPOS` increased to 16,896, because stock v2's allocation cannot hold 16k rows. It fits alongside kvc on this card. Its output bits equal stock v2 at 128, 2048, and 8192 before measuring the session. It also compiles at 64 registers and zero spills. `[measured, session.py; nvcc -Xptxas -v baseline16k.cu]`

At logical 8192, retained live K/V reads fall from 939.52 MB/token to 234.88 MB/token, a 704.64 MB reduction, excluding the new row and weights. Retained scratch for 2048 rows needs 234.88 MB. `[derived, 2 caches * 28 layers * rows * 1024 values * 2 bytes; bench.py/kvc.py]`

## Honest negatives

No answer-quality claim. Keeping the first turn plus the last N complete turns is an example policy, not a tuned choice. The cache allocation retains v2's fixed physical capacity; compaction reduces live rows and decode reads, not the backing allocation. Gather/scatter also needs retained-row scratch.

The decode microbenchmark starts from deterministic varied synthetic cache rows, not an HF-valid 8k conversation. It isolates the scan-length change and uses the real whole-turn GPU compaction API. The 16k session does compute every token through decode and includes dispatch and compaction wall time. It is one scripted session, not 25 session repetitions.

The fp32 masked-reference gate covers a 384-token history with two evictions, not a full 16k HF reference. It finds one permitted near tie, so this is not exact HF greedy-token equivalence. Finite repeats cannot prove race freedom. The retained cache intentionally carries information from formerly visible evicted turns; it is not equivalent to re-prefilling just the retained text.
