## Gate decision

**Correctness PASS; attention scaling targets FAIL; both paths are measured partial merge candidates.** Batch improves ctx128 M4 by 8.00%; causal improves it by 5.96% and improves ctx8192 M4 by 39.79% [derived, `analysis.json`]. Neither standalone mode reaches the full-pass M4/M1 <=1.5 target: causal is 2.0585x and batch 2.0665x [derived, `analyze.py`].

The final warp-private causal implementation wins all sampled contexts, 128/2048/8192. The first tested winning context is 128, with no tested losing context below it. No loss-to-win crossover was observed; an exact threshold below 128 is not measured. No runtime threshold was added because no sampled context requires a fallback [measured/derived, `context_bench.py`, `analysis.json`]. The discarded contiguous-CTA design is not a merge candidate.

## Status

Complete fork: `kernels/megakernel_attn/`; reusable harness and raw samples: `bench/lm20/`. Integration inventory: `kernels/megakernel_attn/CHANGES.md`; unified source diff versus mt2: `kernels/megakernel_attn/mega_mt.diff`.

- Batch distributes `(sequence, head, half)` jobs over all 36 CTAs and two independent warp groups per CTA at M>1. The inherited 32 virtual partitions and partial output format remain unchanged [derived, `attn_batch`].
- Causal warps independently scan the union of their queries' original partition ranges, skipping empty gaps. Each row load into registers serves every matching query. Q operands and partial softmax states remain in registers. Two query columns merge concurrently through the shared partial groups. This removes the long-context CTA-tile serialization [derived, `attn_causal`].
- Both modes build all needed in-block K/V rows locally, append each global row once, and never depend on another CTA's newly appended row. The separate append phase and its grid barrier are removed. This eliminates one grid barrier per layer, 28 per multi-token pass [derived, `mega_mt`, `sched_mt.py`].
- `attn_merge_weights` computes the softmax correction once per virtual partition and shares it across elements. `attn_merge` preserves the original serial sum order and strides over all 130 entries [derived, source].
- Every final selected build uses `--fmad=false`; production thread counts match mt2 at all M. The temporary M5 256-thread exception is removed. Batch inlines; causal outlines at M>1 to separate register lifetimes and inlines at M1 [derived, source/build.sh].

Rows are shared once within each virtual-partition warp's union, not exactly once globally. The long-context request count approaches M1, but dot/softmax work still executes for every query, and M>1 uses 16 physical warps versus M1's 32 [derived, source/model]. These facts do not by themselves identify the measured hardware bottleneck; no DRAM/issue counter attribution was collected.

## Honest negatives

1. **Both slice targets and the standalone full-pass <=1.5x goal are missed.** The fork improves pass latency but cannot claim the wave-wide goal. Its remaining GEMMs and `pro_attnc` are unchanged.
2. **The first contiguous-CTA causal design was rejected.** At ctx2048 M4 it took 24.983809 ms versus mt2's 7.891520 ms. Its ctx8192 job had already finished when the skip instruction arrived: 108.524414 ms versus 21.546623 ms. Do not confuse those rejected samples with the final warp-private results [measured, `contiguous-context-2048.json`, `contiguous-context-8192.json`]. At long context, a 32-row tile covers only roughly one to three original virtual partitions, leaving most physical warps idle at repeated CTA tile barriers [derived from the discarded partition/tile bounds]. That code is removed.
3. The batch burst-load alternate spilled at M4: 32 bytes spill stores and 64 bytes spill loads. It was killed before GPU timing and restored to the selected serial virtual-partition loop [measured, `build-burst-m4.log`].
4. An early hardened invocation omitted candidate numerical metadata and used the contracted LM-14 sequential library. Supplying `gate_contract.json` fixed the harness contract; no tolerances were relaxed. A temporary 256-thread M5 also exposed missing partial elements 128/129 in a narrower group. The strided merge fixes that boundary, and final M5 is back to baseline 512 threads [measured, earlier gate evidence; source and final gate.json].
5. Phase sums are CTA0 diagnostics with sampled unlocked clocks, not exact full-pass retirement attribution. The removed append barrier's isolated waiting time is not measured; only all-grid-barrier cycles are available. No claim of measured DRAM-byte reduction is made.

The exact causal performance boundary below ctx128 remains uncharacterized; the evidence supports the candidate at all three sampled contexts, not an invented crossover threshold.
