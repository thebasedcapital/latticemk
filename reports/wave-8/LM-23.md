## Gate decision and status

The merged kernel is complete and passes the requested correctness gates. It is not a <=1.5x performance success. Causal M4/M1 is 1.8879x at ctx128, 2.4645x at ctx2048 and 2.8142x at ctx8192 [derived, `analysis.json`]. The short-context M4 pass saves 18.44% versus mt2, and ctx8192 saves 42.39% [derived, `bench.py` medians].

**It is worth building CPU prompt-lookup or n-gram speculative decoding on this kernel for short context, ctx128.** This is a cost-based recommendation, not a measured end-to-end speculative speedup. At ctx2048, build it for workloads whose mean accepted draft prefix exceeds 1.4645 of three draft tokens at M4. At ctx8192, do not enable it by default without an acceptance trace above 1.8142 of three and room for host overhead. All-accepted M4 speedup ceilings are 2.1188x, 1.6230x and 1.4214x respectively [derived, `analyze.py`; assumed approximately zero CPU drafting cost and one target bonus/rejection token per pass]. Long context can still benefit on repetitive text, but this measurement does not establish that such acceptance occurs.

Owned deliverables are `kernels/megakernel_mt3/`, `bench/lm23/`, this report, and additive gate support in `gate/debug.py`, `contract.py`, `layers.py` and `README.md`. No GEMM change from LM-22 was merged. `research/` and git state were not written.

## Merge and resource proof

`MERGE.md` records the only textual conflict, LM-20's larger shared Q/KV and merge scratch versus LM-21's removal of the old norm scratch. The global 130-float partial row remains unchanged. LM-20 writes each column's accumulator/denominator/maximum, and LM-21 reads that same global row. Shared `u.wpart` is private intermediate storage, not their interface.

The fused LM-20 schedule is retained, including removal of the separate append barrier. The main loop uses the all-column LM-21 prologues and epilogues. Companion detail wrappers were reconciled by signatures, not copied blindly. GEMM headers, packed weights, cache layouts and the host ABI are unchanged.

### Initial tier-3 failure and calibration repair

The first mt3 causal M4 run passed tiers 1-2 and the local layer probe but failed the full-chain layer probe. The unchanged mt2 M4, under the same `--fmad=false` contract, produced exactly the same 19 full-chain failures. The first was attention layer 7 at prompt-0 position index 58. V2 still passed [measured, `tiers.jsonl`, `regression-tiers.jsonl`]. This is a mismatched calibration contract, not evidence of a merge-only numerical defect.

With integrator approval, the gate now selects a trusted calibration library by compiler flags and the complete thread table in `gate_contract.json`. Default LM-14 still uses `megakernel_mt`. The accepted noncontracting contract uses unchanged `megakernel_mt2`. Unknown contracts fail closed. A candidate cannot nominate itself as the calibration baseline. Debug manifests bind source, binary, headers and flags.

Temporary metadata probes also exercised both trusted selections, a candidate calibration-path nomination that must be ignored, and rejection of unknown flags or a changed thread table [measured, inline contract selection smoke to `contract-smoke.json`]. No temporary files remain.

The new mt2 envelopes use the exact existing LM-17 procedure: all prompt positions plus the first 63 forced outputs across three prompts, 213 positions; independent full-chain and local probes; every layer's hidden/attention max-absolute and RMS; unchanged multiplier k=1.25 [measured/procedure, `gate/layers.py` to `bench/lm23/calibration.json`]. No HF reference values, tier-1/2 bounds or multiplier were loosened. Both observed envelopes, fixed bounds, calibration tokens and hashes are retained in that JSON. The causal M4 mt2 and mt3 reruns pass every tier; default LM-14 and v2 also pass after this change [measured, `contract-tiers.jsonl`].

`gate/debug.py` separately adds an all-column P2 hook. It captures the actual rounded half2 attention staging values and injects local HF inputs through the existing column norm storage. Scalar-column instrumentation remains on its original path. The uninjected association checks pass before tier-3 comparisons, and the stronger M1 dump-enabled raw-bit proof above also passes. `gate/README.md` describes the hooks and trusted-contract selection.

## Speculative break-even

Let r(k)=t(k)/t(1). If a verify pass commits only its accepted draft tokens, mean accepted tokens must be strictly greater than r(k). Equality only breaks even. This is the requested acceptance-only cost calculation.

For this actual causal ABI, M=k includes the already-known anchor token and up to k-1 draft inputs. A standard greedy verifier can commit the accepted draft prefix A plus one target token, either a correction at rejection or the bonus after all drafts match. Then speedup is `(E[A]+1)/r(k)` and the threshold is `E[A] > r(k)-1`. The second threshold column states that convention explicitly rather than silently crediting an extra token. It assumes the host implements the anchor/rollback/bonus semantics correctly; no speculative host loop is part of LM-23.

Every table number is [derived, `analyze.py` from the paired causal full-pass medians]. Drafting cost is [assumed] approximately zero for CPU n-gram/prompt lookup. Host validation, cache rollback and launch orchestration costs are not measured. Accepted prefixes, not arbitrary independent per-token matches, count toward these means.

| Context | k=M | t(k)/t(1) | Minimum mean, accepted-only | Minimum mean accepted drafts, anchor+target convention | Draft-capacity fraction threshold | All-accepted speedup ceiling |
|---|---:|---:|---:|---:|---:|---:|
| 128 | 2 | 1.3267 | > 1.3267 | > 0.3267 of 1 | 32.67% | 1.5075x |
| 128 | 3 | 1.5843 | > 1.5843 | > 0.5843 of 2 | 29.21% | 1.8936x |
| 128 | 4 | 1.8879 | > 1.8879 | > 0.8879 of 3 | 29.60% | 2.1188x |
| 2048 | 2 | 1.7088 | > 1.7088 | > 0.7088 of 1 | 70.88% | 1.1704x |
| 2048 | 3 | 2.0972 | > 2.0972 | > 1.0972 of 2 | 54.86% | 1.4304x |
| 2048 | 4 | 2.4645 | > 2.4645 | > 1.4645 of 3 | 48.82% | 1.6230x |
| 8192 | 2 | 1.8485 | > 1.8485 | > 0.8485 of 1 | 84.85% | 1.0820x |
| 8192 | 3 | 2.3016 | > 2.3016 | > 1.3016 of 2 | 65.08% | 1.3035x |
| 8192 | 4 | 2.8142 | > 2.8142 | > 1.8142 of 3 | 60.47% | 1.4214x |

At ctx128 M4, even the conservative accepted-only model needs fewer than two accepted tokens per pass. Under the actual anchor convention the threshold is 0.8879 of three drafts, with a 2.1188x all-accepted ceiling. At ctx8192, M2 has only a 1.0820x all-accepted ceiling, so minor host costs can erase its gain. M4 has more room but requires a longer accepted prefix. Those are cost facts, not acceptance measurements.

## Honest negatives and open threads

- The combined fork misses <=1.5x everywhere. Short-context gains from the two slices do not remove the inherited CUDA-core GEMM scaling cost.
- Independent batch ctx2048 M3 regresses by +0.377184 ms and M5 by +0.759488 ms versus mt2. Causal ctx8192 M1 regresses by +0.086432 ms [derived, `analysis.json`]. Do not claim the merge wins every row.
- The original merged M1/M5 build spills; only the structurally fixed production binaries are timed. The lower-thread alternative is measured and loses. The isolated noinline-call overhead at the original spilling thread configuration is not measurable without timing a rejected binary.
- The first full-chain tier-3 comparison failed. It remains in the retained evidence, alongside the identical mt2 failure and the approved contract-keyed repair. It is not relabeled a PASS.
- No speculative acceptance trace, real host verification/rollback loop, stochastic sampling implementation, hardware DRAM/issue counters or end-to-end speculative speedup was measured. Clock-derived phase sums are not used to manufacture CUDA-event attribution.
- No implementation or gate job remains for LM-23. The next product decision is whether real lookup acceptance clears the table's thresholds with host costs included. The evidence supports building the short-context path first, and making long-context enablement conditional on observed accepted-prefix length.

## Reproduction

Run from the repository root. GPU commands are bounded inside the shared lock wrapper.

```sh
bash kernels/megakernel_mt3/build.sh selected
.venv/bin/python kernels/megakernel_mt3/sched_mt.py
scripts/gpu.sh timeout 285 .venv/bin/python bench/lm23/check_gate.py
.venv/bin/python bench/lm23/run_gates.py
scripts/gpu.sh timeout 285 .venv/bin/python bench/lm23/check_dump.py
.venv/bin/python bench/lm23/run_timings.py
.venv/bin/python bench/lm23/build_trade.py
scripts/gpu.sh --timing timeout 285 .venv/bin/python bench/lm23/trade.py
.venv/bin/python bench/lm23/analyze.py
```

`run_gates.py` performs the four requested candidate configurations plus v2 and mt2 regressions. `contract-tiers.jsonl` retains the qualification of mt2, mt3, v2 and default LM-14 after calibration selection was corrected. `results.jsonl` contains 54 measured primary timing rows with raw samples. The trade session is separate. Append-only results preserve previous runs; do not mix their absolute times across sessions.
