# LM-13 — native EXL2 baseline

## Gate decision

The 4.65-bpw EXL2 decoder with a 6-bit head lands inside the prespecified 5% quality band: PPL **12.876691** versus v2-GPTQ **12.4435** (EXL2 3.48% worse). Native quantization and quality gates are complete; paired decode speed at three contexts decides the baseline.

ExLlamaV2's native per-layer quant-attention/MLP CUDA graphs and PyTorch SDPA for *single-token* attention are enabled; FlashAttention-2 and xFormers are unavailable on this configured Turing environment. ExLlama events bracket one `model.forward` with a warm fp16 KV cache at fixed depth and include GPU embedding transfer, quantized matvecs, attention, logits **and any GPU-idle gaps while Python issues the next kernels**. They exclude sampling and CPU logits copy, but do **not** isolate device execution from host dispatch; this can disadvantage ExLlama's Python-driven layer loop against v2's persistent launch. V2's event encloses an eight-step persistent launch and divides by eight; its in-kernel argmax is included. Cache prefill is untimed for both. ExLlama needs explicitly causal non-SDPA prefill because the installed SDPA branch is wrong for multi-token inputs; switching to SDPA for one-token decode is safe. Both paths use batch 1, the same cache depth and fp16 KV. EXL2 external kernel spill counts were not checked. `[measured timing mode, bench/lm13/paired.py; graph condition, exllamav2/exllamav2_ext/cuda/q_attn.cu:173–195]`

The stock converter completed in 196 s. `[measured, bench/lm13/run.sh -> exllamav2.conversion.convert_exl2, transcript artifact://750]` The faster corrected 4.125-bpw decode path at ctx128 gives v2-GPTQ **565.0 tok/s** versus EXL2 **172.0 tok/s**, 30 samples each in one process; EXL2 PPL **15.7505** is not quality matched to v2's **12.4435**, so this ratio is a hardware observation, not a matched-quality result. `[measured, bench/lm13/paired.py -> bench/lm13/results.jsonl; derived, ratio of paired medians]`

Matched llama-perplexity protocol: tokenize the same WikiText-2 raw test once, reset KV for each of 146 non-overlapping 2048-token windows, score only positions 1024–2046 against the next token. EXL2 4.125-bpw decoder/4-bit head has **PPL 15.750495**, versus v2-GPTQ **12.4435**, Q4_0 **12.9617**, Q4_K_M **12.1664**, F16 **11.2031**. `[measured, bench/lm13/ppl.py --headnorm-corrected --no-sdpa --start 0/50/100 --count 50/50/46, bench/lm13/aggregate_ppl.py, bench/lm13/ppl_parts.jsonl; reference bench/lm11/ppl.json]` EXL2's own forward with fp16 cache and fp16 logits supplies NLL. Cross-engine arithmetic differs; the windows, tokenizer, positions and scored-token count (149,358) match.

At 5.0-bpw decoder/6-bit head, EXL2 reaches **11.797050** PPL on the same 149,358 tokens. Its streamed-weight proxy is **402,556,328 bytes/step** versus v2's **316,616,704** (+27.1%). This is better quality at a higher rate, not an equal-rate or exact-quality match. `[measured, bench/lm13/ppl.py and aggregate_ppl.py; derived, safetensors tensor-header accounting as in bench/lm13/paired.py; reference bench/lm11/ppl.json]`

The **higher-quality** 5.0-bpw model was also paired, not merely scored: v2 / EXL2 tok/s is **579.7 / 142.7** at ctx128 (SM median 1725 MHz), **401.7 / 101.2** at ctx2048 (1545 MHz), and **215.1 / 31.6** at ctx8192 (1545 MHz). Each of the three pairs has 30 alternating samples per engine; comparing 5.0 against 4.65 across separate clock-unlocked sessions would *not* be a paired result. `[measured, bench/lm13/paired.py --exl2 baselines/exl2/qwen3-0.6b-5bpw-causal --ppl 11.797050 -> bench/lm13/results.jsonl]`

The quality-matched 4.65-bpw checkpoint streams **383,275,314** estimated weight bytes/step against v2-GPTQ's **316,616,704** (+21.1%). The EXL2 head uses 6.53 effective bpw. Quality is within 5%; rate is not. `[derived, safetensors tensor-header accounting in bench/lm13/paired.py; measured, bench/lm13/ppl.py]`

The source has two Qwen3 bugs. It treats Q/K RMSNorm as LayerNorm (`architecture.py:220,435–446` and `headnorm.py:132–137`), and its Torch SDPA branch passes no causal mask for multi-token prefill (`attn.py:889–903`). On WikiText's first 2048-token window, unmodified ExLlama dense PPL is **59.498**; fixing headnorm alone gives **38.260**; setting `no_sdpa=True` as well gives **9.63618**, matching HF fp16 **9.63661**. `[measured, bench/lm13/ppl.py --start 0 --count 1; bench/lm13/hf_control.py]` The corrected path retains ExLlama's fused quantized-attention/MLP CUDA graphs for decode; `no_sdpa` changes multi-token prefill and fallback attention only.

## Honest negatives

The converter's calibration perplexity (1001.9056) is *not* WikiText-2 test perplexity and cannot support any matched-quality claim. `[measured, converter output artifact://750]` The default EXL2 head strategy was 6.53 effective bpw rather than the decoder's 4.125 bpw. `[measured, same converter]`

The stock 6-bit-head EXL2 model scores **178.189** PPL on the first window while HF fp16 scores **9.637**. `[measured, bench/lm13/ppl.py --start 0 --count 12; bench/lm13/hf_control.py]` It is not a quality-matched baseline. Its converter-calibration PPL of 1001.9 was an early warning, not a WikiText score.

EXL2 4.125-bpw streams **313,657,872** estimated weight bytes per step, including one 2,048-byte CPU embedding row and excluding the non-streamed 311,164,928-byte CPU embedding table; v2-GPTQ streams **316,616,704** packed weight bytes. Similar traffic did not buy similar quality: EXL2 PPL is 26.58% higher. `[derived, safetensors tensor-header size accounting in bench/lm13/paired.py; measured PPL in ppl_parts.jsonl and reference bench/lm11/ppl.json]`

At nearly equal streamed weight traffic, 4.125-bpw EXL2 is **slower** than v2 but materially **worse** quality: paired tok/s (v2 / EXL2) at ctx128 **565.0 / 172.0** (SM median 1680 MHz), ctx2048 **411.4 / 109.3** (1710 MHz), ctx8192 **214.6 / 31.8** (1545 MHz). Each pair has 30 alternate-order samples per engine; these are not quality-qualified speedups. `[measured, bench/lm13/paired.py -> bench/lm13/results.jsonl; measured PPL, bench/lm13/ppl.py]`

An initial ctx128 trial left `no_sdpa=True` even for one-token decode, yielding EXL2 **123.4 tok/s** versus v2 **558.2 tok/s**. Multi-token prefill needs explicit causal masking, but one-token decode may use Torch SDPA safely. Enabling SDPA *only after prefill* improved the EXL2 median to **172.0 tok/s** in a separate paired run; these two trial medians were not clock-paired with one another. `[measured, bench/lm13/paired.py -> results.jsonl]`

## Open threads

Only the installed native per-module CUDA graphs plus Torch SDPA were measured: this is **not** a claim about the fastest possible EXL2 path with an untested whole-model graph or an additional Turing-compatible attention extension. The 1.7B model was not converted or measured. If comparing a future external engine, keep the quality gate and the same-process alternating timing protocol before adding it to a public headline.
