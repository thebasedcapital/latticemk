## 3. Design

Happens-before is computed exactly, without an O(n²) bitset closure:

- **Virtual flag nodes.** Each declared flag with exact waits becomes one graph
  node; edges are `setter → F` and `F → waiter`. This encodes the full
  setter→waiter edge set in O(#setters + #waiters) edges instead of O(S·W).
  Deadlock = any cycle in this graph (task i that both sets and waits flag F
  with v = 1 correctly becomes the 2-cycle i→F→i).
- **hb matrix.** `hb[node][b]` = 1 + program position of the latest task of
  block `b` that happens-before `node` (0 = none). Rows merge by componentwise
  max during the Kahn pass, seeded so each task sees its own position.
  Task t1 hb task t2 ⟺ `hb[t2][t1.block] > pos[t1]` — each block is a chain,
  so one u32 per (node, block) is exact. Memory `(N+F)·B·4` bytes; a DFS
  fallback (`hb_depth` recomputed by reachability) covers schedules where the
  matrix would exceed 512 MiB (≈ 50k tasks needs blocks ≤ ~2600).
- **Race check.** Per buffer, accesses are grouped into classes of identical
  `(begin, end, is_write)`; classes are interval-swept (sort by begin +
  min-heap on end) so only *overlapping* class pairs are visited. Every
  conflicting access pair sits inside an overlapping class pair, so nothing is
  missed. For each class pair and block pair `(c1, c2)`, an unordered
  access pair exists iff `∃ a,b: pos_a ≥ hb[b][c1] ∧ pos_b ≥ hb[a][c2]`;
  evaluated by sorting `A@c1` by pos and keeping a suffix-min of `hb[a][c2]`
  — O(|A| log |A| + |B|) per block pair instead of O(|A|·|B|). Individual
  violations are enumerated up to 4096 per file, then counted.

This matters in practice: a naive per-access-pair sweep took 3.9 s on the
50k-task synthetic (phase-reused buffers give ~5·10⁷ real conflict pairs);
the class-pair formulation takes ~64 ms for the races stage `[measured]`.

**Complexity** (N tasks, B blocks, F flags, C access-range classes per buffer,
L overlapping class pairs): structural O(N + A), exactness O(N), graph +
Kahn + hb build O((N+F)·B + E·B) with E = O(N), races O(C log C + L) class
pairs × O(B² · (|A| log |A| + |B|)) worst-case block-pair queries.

## 5. Honest negatives / limits

- The DFS fallback path (`hb` matrix > 512 MiB, i.e. ~2,600+ blocks at 50k
  tasks) is implemented and exact but not performance-tested at scale — real
  persistent kernels have ≤ ~1k blocks, so this is theoretical headroom.
- Violation enumeration caps at 4,096 per file (then counts): a schedule with
  more races prints the first 4,096 task pairs plus a per-(class, block-pair)
  remainder count rather than every pair.
- `waits`/`sets` on a *non-exact* flag are excluded from the hb graph (the
  file is already rejected); races on such files are still reported when the
  graph stays acyclic.
- CPU timing only — this package never touches the GPU (no `gpu.sh` needed).
