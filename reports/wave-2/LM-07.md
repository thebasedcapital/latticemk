# LM-07 — KV-cache codec feasibility (prep for D-02)

2026-09-30 · Quadro RTX 4000 (sm_75) · driver 610.57.04 · torch 2.11.0+cu128 · transformers 5.17.0
Package dir: `kvcodec/` · results: `kvcodec/results.jsonl`, `kvcodec/stats.json`
Sample: K/V (K post-k_norm + post-RoPE — exactly the cache content; V post-v_proj) for
3 x 2048 wikitext-2 test windows + Q for window 0, stored fp16 in `kvcodec/data/` (940 MB)
by `kvcodec/capture.py` (`scripts/gpu.sh .venv/bin/python -m kvcodec.capture`).

## 1. Gate decision

| question | answer | evidence |
|---|---|---|
| Is ~2.4 b/coord at INT4-level distortion information-theoretically possible on Qwen3 KV? | **K: yes** — SLB 1.98 b/coord vs 2.41 available; **V: no** — SLB 3.35 | `kvcodec/stats.py` -> `kvcodec/stats.json` `[derived]` |
| Do 2.4 b/coord baselines reach INT4-level quality? | **No.** Best stand-in (A2-k5+rht, 2.625 b) gives ppl 434 vs INT4-token 156 vs KIVI-int4 15.5 vs fp16 12.66 | `kvcodec/eval.py` -> `results.jsonl` `[measured]` |

The D-02 claim (2.41 b @ INT4 distortion) can only hold on KV **as a K-only (or asymmetric)
claim**: V's Shannon floor at INT4-V distortion is 3.35 b/coord. And "INT4 distortion" is itself a
bad target here — plain per-token INT4 KV is quality-fatal on this model (ppl 155.7); the real
bar is KIVI-int4's 15.5.

## 3. Headline numbers

Sample: 3 windows x 28 layers x 2048 tok x 8 heads x 128 dims = 44.0 M coords per kind
`[measured]` (`kvcodec/stats.py`).

**KV statistics** `[measured]`:
- K per-token-normalized: h = 1.125 bits, excess kurtosis +39.2 — sharply peaked, heavy-tailed;
  layer-0 heads 2/6/7 carry channel-RMS outliers up to 231x median.
- K after a 128-dim RHT: h = 1.914 bits, kurtosis -0.65 (sub-Gaussian — the rotated head vector is
  in the bounded, simplex-like regime A_n is built for).
- K per-channel-normalized is near-Gaussian (h = 2.038, kurt -0.04): K outliers are channel
  outliers — the KIVI story.
- V is near-Gaussian everywhere: h = 2.024 / 2.025 / 2.043 bits (per-token / per-channel / RHT),
  kurtosis +1.4.

**INT4 SQNR targets** `[measured]`: K per-token 16.75 dB · K per-channel 9.73 dB ·
V per-token 19.58 dB · V per-channel 19.51 dB.

**Shannon lower bound** at INT4 SQNR, scale metadata incl. (`[derived]`; assumes i.i.d. given the
scale `[assumed]`; per-token overhead +0.125 b, per-channel +0.25 b):

| source/scaling | h (bits) | SLB @ INT4 SQNR | vs 2.41 b |
|---|---|---|---|
| K per-token | 1.125 | **1.98 b/coord** | feasible — 0.43 b headroom |
| K per-channel | 2.038 | 1.86 @ 9.73 dB | feasible but the target is 7 dB weaker than per-token INT4 |
| K per-token + RHT | 1.914 | 2.77 | not feasible — rotation erases the heavy-tail gain |
| V per-token | 2.024 | **3.35** | not feasible (the wave-1 weights story) |
| V per-channel | 2.025 | 3.47 | not feasible |

**Measured codecs** (`kvcodec/eval.py`; SQNR pooled over layers; ppl = wikitext-2 test
146 x 2048, fp32 model, fake-quantized cache writes, query + current-token K/V exact;
attn err = rel output error vs fp16 at ctx 2048, pooled over 28 layers) `[measured]`:

| codec | b/coord | SQNR K | SQNR V | attn rel err | **ppl** |
|---|---|---|---|---|---|
| fp16 | 16.0 | inf | inf | 0.000 | **12.66** |
| int8 per-token | 8.25 | 36.9 | 43.7 | 0.019 | **12.74** |
| int4 per-token | 4.25 | 16.7 | 19.6 | 0.263 | **155.7** |
| kivi-int4 (K per-ch, V per-tok) | 4.25 | 9.7 | 19.6 | 0.253 | **15.46** |
| kivi-int2 | 2.25 | 9.3 | 8.1 | 1.088 | **166.3** |
| A2-k5 (stand-in, NOT D-02) | 2.625 | 3.0 | 11.6 | 1.462 | **3653** |
| A2-k5+rht | 2.625 | 15.4 | 12.3 | 0.436 | **433.7** |
| A4-k9 | 2.375 | 3.8 | 10.9 | 1.485 | **10943** |
| A4-k9+rht | 2.375 | 13.1 | 11.3 | 0.487 | **1250** |
| A4-k10+rht | 2.625 | 14.5 | 12.6 | 0.427 | **946.5** |

Two things stand out:

- **SQNR is the wrong ranking metric for KV.** int4 per-token beats kivi-int4 on SQNR
  (16.7/19.6 vs 9.7/19.6 dB) and ties on attn error, yet loses ppl by 10x (155.7 vs 15.5).
  Preserving K's channel-outlier geometry (per-channel scaling) matters more than raw MSE.
- **The A_n stand-in is far from INT4-distortion even with RHT** (best 15.4 dB K vs INT4's 16.75,
  and V is stuck ~12.6 dB vs 19.6), and ppl is catastrophic (>= 434). If D-02's 2.41 b/coord is
  real, it is beating this codebook by > 4 dB on V alone — check that first when it lands.

**Byte model** (`kvcodec/byte_model.py`, `[derived]`; weights INT4 316.6 MB/tok `[measured, wave-1]`,
roofline 406.7 GB/s `[measured]`; tok/s = roofline / bytes-per-token — upper bound, ignores
attention FLOPs):

| ctx | KV fp16 MB/tok | KV int4 | KV @2.375 b | total @2.375 b | tok/s bound fp16 -> 2.375 b |
|---|---|---|---|---|---|
| 128 | 14.7 | 3.9 | 2.2 | 318.8 | 1228 -> 1276 |
| 2k | 234.9 | 62.4 | 34.9 | 351.5 | 737 -> 1157 |
| 8k | 939.5 | 249.6 | 139.5 | 456.1 | 324 -> 892 |
| 32k | 3758.1 | 998.2 | 557.8 | 874.4 | 100 -> 465 |

KV reads pass INT4 weight bytes at ~2,760 ctx (fp16), ~10.4k (int4), ~18k (2.375 b) `[derived]`.
At 32k a ~2.4 b/coord KV codec lifts the roofline bound 4.6x with weights untouched.

## 4. Honest negatives

- **V cannot reach INT4-V distortion at 2.4 b/coord** — SLB 3.35 (near-Gaussian source, same as
  wave-1 weights). A D-02 eval must be K-only or mixed-rate, or the claim fails on arrival.
- **Plain per-token INT4 KV is quality-dead** (ppl 155.7) despite decent SQNR; "matched distortion"
  to it is a straw target. KIVI-int4 (per-channel K) is the honest INT4 bar at 15.5.
- **A_n truncated-ball stand-ins are not near the D-02 claim on KV**: best 2.375-2.625 b config
  reaches only 13.1-15.4 dB on K (vs needed ~16.75 to match INT4) and ~12 dB on V (vs 19.6);
  ppl >= 434 at every lattice point tried. RHT is mandatory (without it K SQNR is 3-4 dB).
- fp16 capture bounds SQNR measurement to the fp16 noise floor — irrelevant at the ~10-20 dB
  working point.
- ppl used eager attention with the diagonal-exact correction; the A_n Python+CUDA encode adds
  ~15-20 ms/window/layer — an eval cost only, not a codec claim.

## 5. Open threads / how to plug in D-02

`D02` in `kvcodec/codec.py` raises `NotImplementedError` with these steps:

1. Vendor the D-02 codec (from `machine-proof-builds/`, unavailable on this machine) into
   `kvcodec/`, or extend the `sys.path` shim in `codec.py` to import it.
2. Implement `encode(x [T,8,128] fp32 cuda, kind 'k'|'v') -> Packed` and `decode(Packed) ->
   [T,8,128]`; set `Packed.bits` to the true packed size (codes + scales + side info) — the
   harness reports `bits_per_coord` straight from it. If D-02 works on RHT'd vectors, do the
   rotation inside encode/decode (`An._fwd/_inv` is a template; per-head seeds supported).
3. Run: `scripts/gpu.sh .venv/bin/python -m kvcodec.eval --codecs d02` — produces the full
   results.jsonl row (bits, SQNR K/V, attn rel err @2048, ppl 146x2048) in ~5 min.
4. Compare: feasibility floor K SLB 1.98 b; quality bar KIVI-int4 ppl 15.46; stand-in ceiling
   A2-k5+rht 15.4 dB / ppl 434.
5. If D-02 is K-only, evaluate the mixed point "d02-K + int4-V" (a `Mixed` codec is a two-line
   wrapper like `Kivi`): at 32k ctx that still cuts total bytes 4.7x vs fp16 KV `[derived]`.

Deviations from spec (disclosed): sample is 3 windows (6144 tok/layer), attention error on one
2048-token window across all layers; no Nsight Compute (not installed) — bandwidth numbers are
bytes/time-derived; quality runs are fp32 not bf16 (spec asks bf16 reference — transformers loads
this checkpoint fp32 here; wave-1 ppl used the same fp32 convention, so numbers are comparable).
