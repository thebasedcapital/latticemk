## Method and hyperparameters

Source: [Explore Broadly, Reason Sharply: Push Small Models toward the Frontier via Sampling, arXiv:2609.38104](https://arxiv.org/html/2609.38104), Sections 2 and 3, Appendix B Algorithm 1 and Appendix G Table 6.

`ppt/sampler.py` implements progressive fixed-horizon PPT. GSM8K uses the paper's exact Qwen3 configuration [assumed, paper Table 6]:

| parameter | value |
|---|---|
| replicas K | 6 |
| powers | 2.0, 2.3, 2.6, 3.0, 3.5, 4.0 |
| proposal temperatures | 1/2, 1/2.3, 1/2.6, 1/3, 1/3.5, 1/4 |
| maximum horizon | 3072 |
| block size | 192 |
| blocks | 16 |
| local rounds per replica per block | 10 |
| restart | uniform over every position in the current horizon |
| swaps | one ordered adjacent sweep after every local round |
| output | final coldest rung, alpha=4 |
| top-p / top-k / min-p | 1 / disabled / 0 |
| model precision | fp16 weights and inference, fp32 scoring |

Each token carries its base-model log probability and all six tokenwise log normalizers. The local log acceptance ratio is the sum of the proposed-minus-current normalizers on the regenerated suffix, using the receiving rung's power. The swap log ratio is `(alpha_right-alpha_left)*(logp_left-logp_right)`. Accepted swaps move the record and every score array. Deterministic padding after termination has zero log score. Restarting at or before EOS can lengthen a record through the fixed horizon; restarting after EOS does nothing and generates no tokens. No realized-length restart restriction is used.

### Engine and deviations

The engine is HF transformers with SDPA and KV-cache decode. All logits participate in fp32 `log_softmax` and `logsumexp`; neither top-token log-probability truncation nor quantized weights are used. Proposals batch the active rungs. Prefixes are re-prefilled at every proposal instead of reusing paged prefix KV handles, and prefill tokens are counted separately from generated tokens. For an exact, shape-independent model this changes runtime rather than the proposal law; the measured fp16 shape drift below prevents that exact-invariance claim for this engine. Completed or capped members remain padded in a decode batch until its longest member finishes, so actual GPU decode work can exceed generated tokens.

The six-rung physical batch hit CUDA OOM at horizon 1152, after saving 55 of 160 local rounds, 94,587 generated tokens and 1,205.602 inference seconds [measured, `ppt/run.py` -> `ppt/oom.json`]. The exception arose in SDPA's repeated KV-head allocation. Variable restart positions combine the longest padded prefix with the longest regenerated suffix, so physical KV length can approach twice the nominal horizon [derived, `ppt/sampler.py`]. Continuation groups model requests into at most two simultaneous sequences above horizon 768. K remains six; extension, all local attempts, uniform restart laws, six-power score caches, ordered swaps, and the returned rung are unchanged. Execution order, CUDA RNG consumption and fp16 batch-shape rounding change. The intended mathematical proposal remains full-vocabulary temperature sampling, but exact floating-point target invariance is not established. `ppt/checkpoint-before-microbatch.json` preserves the pre-change state. `ppt/chunks.jsonl` charges the failed invocation's elapsed time; saved inference counters omit unsaved failed work.

Paper prompting is incompletely specified. These base checkpoints use their provided chat template, `enable_thinking=False`, with the same explicit step-by-step instruction for every method. The final-answer format is `#### <number>`. The terminal set contains `<|endoftext|>` and `<|im_end|>`, and their token probabilities are included. This prompt and terminal configuration are recorded deviations from unspecified paper details, not tuned against held-out answers.

The GSM8K subset is 200 distinct test problems, sampled with Python `random.Random(719)`. `ppt/gsm8k.json` stores source URL, the full-source SHA256, original test indices, questions, and normalized answers. Numeric exact-match extraction accepts explicit `####` or numeric `\\boxed{}` answers, normalizes commas and decimal notation with `Decimal`, and scores missing answers as incorrect. No correctness verifier enters sampling or ranking.

## Verification

`.venv/bin/python ppt/test_sampler.py` passes seven scoped tests [measured, `ppt/sampler-proof.json`]. The paper's binary-EOS horizon-2 example targets probabilities 2/3, 1/6, 1/6. A 100,000-update run measured 0.665707, 0.167596, 0.166697 after discarding 1,000 updates, with 8,282 accepted EOS-to-longer transitions and 0.916 local acceptance [measured, `ppt/test_sampler.py`]. A negative swap log ratio of -1 accepted 0.36843 of 100,000 attempts versus the exact 0.367879 target [measured/derived, same script]. The ordered adjacent sweep moves records `[0,1,2,3]` to `[1,2,3,0]`, accepting all three favorable exchanges. Other tests verify receiving-power normalizers after swaps, exact checkpoint/resume equivalence, final-budget exclusion, the local acceptance-count invariant, numeric answer parsing, and paired statistics.

The runner writes an atomic checkpoint after every extension and local/swap round, including Python and CUDA generator state, record scores, schedule cursor, counters, and accumulated inference wall time. JSONL rows are appended only for complete problem-method results. Resumed chunks release the shared GPU lock between invocations.

`scripts/gpu.sh .venv/bin/python ppt/check_engine.py` exercises actual six-rung HF generation and captures the original fp16 logits. Independent CPU-float64 evaluation of all 151,936 vocabulary entries agrees with cached token log probabilities to 6.23e-7 and cached normalizers to 2.41e-6 [measured, `ppt/engine-proof.json`]. This verifies full-vocabulary scoring, not agreement between different fp16 execution shapes. A separate teacher-forced batch-1 diagnostic differs by up to 0.021904 in token log probability and 0.077259 in a tokenwise normalizer [measured, the same script]. The first proof incorrectly treated that shape-dependent fp16 difference as an error under an arbitrary 0.05 tolerance. The final proof tests the defining score equations on the same logits and preserves the drift diagnostic rather than raising the tolerance.

At the final horizon-1728 checkpoint, three rungs including the coldest still repeat `paque` separated by newlines, one repeats `.slf`, and another repeats a Chinese fragment. The alpha=2 record contains a terminated arithmetic solution. These are direct decoded outputs [measured, `ppt/inspect_checkpoint.py` -> `ppt/checkpoint-inspection.json`], not an accuracy result; the paused cold record is not graded. Low-temperature decoding on this same problem also reaches the 3072-token cap [measured, `ppt/pilot_baselines.py`]. The sharpening ladder can concentrate on repetitive high-likelihood continuations under this checkpoint and prompt. No repetition penalty, top-k, min-p, or custom stop rule is added to conceal that behavior.

## Matched-token control definitions

`ppt/controls.py` spends exactly the completed PPT row's generated-token count for each control. The standard-temperature pool is shared by three readouts: its last completed trace, highest cumulative base-model likelihood, and majority numeric answer. Vote ties use cumulative likelihood, as in the paper. Missing answers do not vote. The low-temperature pool uses temperature 0.25 and returns its last completed trace. Greedy repeats deterministic generation to consume the same budget and returns the last complete trace, so its extra compute cannot improve the answer. The final budget-limited incomplete trace is charged but excluded from readout and voting. Completed EOS records and full-3072-token censored records are eligible. The reported standard and low-temperature readouts can have a final-budget length-selection effect; this is stated rather than treated as the paper's single ancestral sample.

The single-chain control holds the alpha=4, T=3072 target fixed, draws an initial record, then resamples suffixes with uniform full-horizon restarts until the same token budget is spent. This is the paper's corrected fixed-horizon K=1 ablation, but without its progressive warm start or early-stopping implementation. A final budget-limited incomplete proposal is charged and rejected. Finite compute-budget readout is not a claim of stationarity. This control's changed initialization and stopping rule are deviations, not changes to PPT.

`ppt/summarize.py` reports Wilson 95% intervals and an exact two-sided paired McNemar test. The building rule requires a gain of at least two percentage points and paired p<0.05 against the best accuracy baseline. It refuses a decision below 100 paired items, following the integrator's explicit minimum. The standard, best-of-N, and majority rows share one compute group, so summing their reported wall times would triple-count that pool. Seven scoped tests now pass [measured, `ppt/test_sampler.py`], including exact-budget exclusion of the incomplete final sample and exact paired-test probabilities.
